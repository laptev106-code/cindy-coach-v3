# CINDY V3.0 — Coach Cold-Start / Test Calibration Technical Fix Report

**Date:** 28 September 2026  
**Release:** `CINDY_V30_COACH_COLDSTART_20260928_FIXED`

## Scope

Этот проход доводит холодный старт тренера до минимально рабочего end-to-end состояния:

`Тест → фиксированная тестовая тренировка → реальное выполнение → История → данные тренера → решение → применение → следующая тренировка`

Изменения сделаны точечно. Архитектура V3, Program lifecycle, History ownership и Builder/тренер boundaries сохранены.

## 1. Фиксированный тест

Кнопка `ПРОЙТИ ТЕСТ` больше не использует текущую пользовательскую тренировку.

Тест имеет собственное определение:

- длительность: **5, 10 или 20 минут**;
- по умолчанию: **10 минут**;
- режим: только по времени;
- цели по количеству кругов нет;
- состав всегда одинаковый:
  - 5 подтягиваний;
  - 10 отжиманий;
  - 15 приседаний.

Пользователь не может подменить состав, время или цель текущими настройками тренировки.

После выбора длительности экран Workout сразу переключается на выбранный тестовый состав и длительность.

## 2. Тест изолирован от Builder

Пользовательская текущая тренировка не используется как тестовая конфигурация.

Тест запускается как отдельная frozen session. Во время подготовки и выполнения теста текущий Builder-состав не участвует в формировании тестового `WorkoutSpec`.

После успешного завершения теста стандартный состав теста становится Coach-owned стартовым состоянием. Это необходимо для продолжения существующего V3 ownership contract и строгого сравнения последующих тренировок.

## 3. Таймер и фактическое выполнение

Frozen тестовый `WorkoutSpec` передаётся в реальный Workout runtime до START.

Проверено, что при произвольной текущей настройке пользователя, например `1 минута + пользовательский состав`, выбор теста на `10 минут` приводит к фактической session:

- `mode = time`;
- `plannedSeconds = 600`;
- `target = 0`;
- `targetRounds = null`;
- composition = `5 / 10 / 15`.

Дополнительно исправлено правило application input: time-only тренировки больше не получают ложный `target = 20` из-за подстановки через `||`.

## 4. Завершение теста

Тест считается успешно завершённым только после нормального окончания с достаточной execution fidelity.

Ручная остановка, частичное выполнение или недостаточная fidelity не создают принятую стартовую точку.

После успешного завершения сохраняются данные теста, включая:

- выбранную длительность;
- число завершённых кругов;
- время каждого круга;
- общий фактический результат;
- состав;
- данные измерительного контракта;
- снимок выполненной спецификации.

## 5. Данные теста используются тренером

В `CoachCore` добавлен минимальный слой качественной интерпретации темпа по фактическим временам кругов.

Из последовательности кругов определяется качественный паттерн:

- `STABLE`;
- `ACCELERATING`;
- `DECELERATING`.

Это не новый физиологический показатель и не числовая «оценка формы». Паттерн используется как дополнительный контекст для существующего decision engine.

При замедлении тренер получает более консервативное ограничение на локальное увеличение нагрузки. При устойчивых или улучшающихся сопоставимых данных допускаются варианты упражнений.

## 6. Тренер не ограничен четырьмя готовыми тренировками

Канонические шаблоны:

- `Cindy Classic`;
- `Cindy Classic 10`;
- `Variant Cindy`;
- `Mixed Cindy 15`

остаются отдельным ручным каталогом.

Тренер не выбирает следующую тренировку из этого списка.

После накопления достаточного сопоставимого материала тренер продолжает использовать существующую цепочку:

`История → данные → решение → WorkoutSpec`

и может использовать существующую Exercise Intelligence для:

- сохранения упражнения;
- смены варианта;
- замены упражнения;
- удаления дополнительного упражнения;
- добавления упражнения;
- изменения порядка.

Добавлен regression-тест, который на реальных данных exercise matrix подтверждает возможность `change_variant` без обращения к ручному каталогу шаблонов.

## 7. Доказательства после теста

Приложение не считает три случайные записи History достаточными.

Для адаптивного применения требуется:

1. принятой завершённой тестовой сессии;
2. не менее трёх сопоставимых завершённых тренировок после теста;
3. не менее трёх разных тренировочных дней;
4. отдельное разрешение существующего CoachCore (`application.allowed`).

Application layer использует существующие strict/trend evidence views CoachCore и не создаёт параллельную физиологическую модель.

## 8. Builder / тренер / шаблоны / программы

Сохраняются четыре независимых механизма:

**Тренер** — персональное решение по данным.  
**Готовые тренировки** — ручной выбор пользователя.  
**Программа** — последовательность тренировочных дней.  
**Builder** — ручное изменение текущей тренировки.

Program-only шаблоны не выводятся как обычные ручные готовые тренировки.
